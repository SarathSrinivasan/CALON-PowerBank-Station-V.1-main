Final message contracts.

Exact WEB ↔ MQTT ↔ STM32 messages used by the testing frontend.

1 · WEB → STM32 · RENT_REQUESTED

TOPIC: POWERBANK/001/RENT_REQUEST {"event":"RENT_REQUESTED","station_id":"POWERBANK001","request_id":"REQ-XXXX","customer_id":"CUS-XXXX"}

2 · PLAN SELECTION · LOCAL ONLY

The selected hours and amount are stored in the browser session only. No message is published on POWERBANK/001/RENT_PLAN.

3 · STM32 → WEB · AVAILABILITY

TOPIC: POWERBANK/001/AVAILABILITY {"event":"AVAILABILITY","station_id":"POWERBANK001","request_id":"REQ-XXXX","available":true,"slots":[{"slot_id":"SLOT-02","device_id":"PB-002","available":true}]}

4 · WEB → STM32 · POWERBANK_SELECTED

TOPIC: POWERBANK/001/POWERBANK_SELECT {"event":"POWERBANK_SELECTED","station_id":"POWERBANK001","request_id":"REQ-XXXX","customer_id":"CUS-XXXX","device_id":"PB-002","slot_id":"SLOT-02"}

5 · WEB → STM32 · OPEN SELECTED SLOT AFTER PAYMENT

TOPIC: POWERBANK/001/PAYMENT SLOT-02 Payload is the selected slot ID as plain text, sent only after the payment-success button is pressed.

6 · STM32 → WEB · SLOT_OPENED

TOPIC: POWERBANK/001/SLOT_STATUS {"event":"SLOT_OPENED","station_id":"POWERBANK001","request_id":"REQ-XXXX","slot_id":"SLOT-02","device_id":"PB-002","status":"OPENED"}

7 · WEB → STM32 · RETURN_REQUESTED

TOPIC: POWERBANK/001/RETURN_REQUEST {"event":"RETURN_REQUESTED","station_id":"POWERBANK001","request_id":"REQ-XXXX","customer_id":"CUS-XXXX","device_id":"PB-002","return_id":"RET-XXXX"}

8 · STM32 → WEB · RETURN_ACCEPTED

TOPIC: POWERBANK/001/RETURN_STATUS {"event":"RETURN_ACCEPTED","station_id":"POWERBANK001","request_id":"REQ-XXXX","return_id":"RET-XXXX","device_id":"PB-002","status":"ACCEPTED"}

9 · STM32/WEB · ERROR

TOPIC: POWERBANK/001/ERROR {"event":"ERROR","station_id":"POWERBANK001","request_id":"REQ-XXXX","code":"SLOT_OPEN_FAILED","message":"Selected slot did not open"}
